# ZCode built-in parity inventory

## Scope and evidence boundary

This is the complete source comparison of intrinsic ZCode against the existing
built-in provider contracts, followed by the accepted existing-owner corrections.
The comparison baseline was `f25fc9fcc` (upstream `805e5c29a` merged into devzeus).
The tested implementation also preserves the three subsequent CI commits through
`6fdde2efe`; its final behavioral acceptance snapshot was
`14f2baa8bc1e441b70b29c78ebdedd483b4080fbe47901fee7c90f0882c19f4f`
(Git base plus the recorded working-tree overlay, not a Git commit ID).

Source inspection and runtime proof are different. A present/shared row records
an inspected existing contract, not a claim that every live vendor, platform or
possible response was executed. Corrected rows name the relevant exercised
behavior. The vendor reference is official ZCode 3.18.0, `b95ebaff`; unavailable
proprietary verification/signatures were not recreated.

| Final disposition | Contract rows |
| --- | ---: |
| Present/shared, inspected | 67 |
| Corrected, with isolated behavioral evidence | 25 |
| Justified protocol or settings difference | 10 |
| Not applicable to this provider | 2 |
| Rejected extra guarantee, not a baseline parity defect | 1 |
| Total inspected | 105 |

The corrected rows represent 24 accepted finding IDs: ZS-06 appears in two
surfaces. The rejected candidate ZS-01 would have required a new distributed
financial-handoff guarantee that the compared built-ins do not offer. Local
credential restore does not erase the local native journal; a pre-operation
cross-machine credential snapshot cannot transfer a later pending operation or
establish consensus. No such new product was added.

| Actual compiled terminal UI | PTY Providers → Add → filtered ZCode entry → back/quit passed |

These were sequential targeted batches, not a full-project suite or a claim of
unique test identities across batches. Initial failures exposed invalid test
fixtures (home reset after setup, a non-context-aware proxy client, a derived
nonpersisted debt flag and an invalid/changing fixture account ID). They were
corrected and only the failed/unexecuted paths were rerun. The terminal smoke's
initial harness witnesses were corrected for a clipped footer and separate
Escape/quit events; no production behavior was suppressed.

All runs used isolated Linux source/profile state and loopback-only fixtures or
network isolation. Browser captures and raw test/snapshot logs were retained with
the handoff. No live vendor sign-in, reset, claim or spend was performed; the
installed application, live accounts and services were not changed. A saved old
Z.ai login that already lacks valid business material still requires explicit
re-login after updating; a code fix cannot invent that missing credential.

For the implementation process and commands, see
[Adding a Core-owned provider](builtin-provider-development.md). Owning runtime
contracts remain in [Provider ownership](provider-plugins.md),
[Providers and accounts](providers-accounts.md), and [GUI shell](gui-shell.md).
